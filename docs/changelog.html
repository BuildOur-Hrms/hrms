Section twoBuilt, but not yet visible Needs screens

The logic, the database tables, the rules and the tests are done and passing. What is missing is the pages — nobody can click these yet.

Payroll

Salary components, a monthly payroll run, a preview before you commit, an approval step, a payslip per person, and a CSV export for a finance system to pick up. Deliberately simple, because a separate finance system is intended to own the money side later.

Missing: an HR payroll screen, and a payslip screen for employees.

Documents

Upload and download, document categories, and rules about who may see what — a manager can see a report's training certificate but not their passport. Files are checked to confirm they really are the type they claim to be. Expiry warnings go out 30 days before, 7 days before, and on the day; that nightly job is running.

Missing: an HR documents screen, an employee documents screen, and a documents tab on the employee record.

Why this matters for planning. The hard and risky parts of both — the money arithmetic, and the who-can-see-what rules for personal papers — are written and tested. Each is roughly a screen-building exercise away from being usable, not a rebuild.

Section fourHow it is being built

Context for anyone judging whether this is solid.

Every change is checked automatically

781 automated tests run on every single change, and nothing reaches the main branch unless all of them pass: 415 checking calculations in isolation, 307 running real requests against a real database, and 59 driving an actual browser through journeys like signing in, checking in, and requesting leave.

One company cannot see another's data

Two independent layers enforce this. The application always filters by company, and the database itself refuses to return another company's rows even if the application forgets. Both are tested on every endpoint.

Permissions are checked, not assumed

Every endpoint is crossed against all four roles in a generated test grid, so a permission that quietly stops being enforced fails the build.

Everything important is written down

Who did what, and when, goes to an audit log that cannot be edited afterwards — including sign-ins, approvals, and anyone opening somebody's documents.

Section fiveSuggested next step

One recommendation, and the reasoning behind it.

Build the payroll screens next. It is the largest piece of finished work currently sitting invisible, the export to a finance system is already written and tested, and it depends on month-locking, which has been working since the attendance module shipped. Documents is the natural one after it.

Honest caveats

  • Payroll has not yet been run in parallel against a real manual payroll for a full month. That comparison should happen before anyone is paid from it.
  • The restore drill has not been performed. Backups existing is not the same as knowing they work.
  • Custom roles are not available, so the four built-in roles have to fit how the company actually works.
  • The system has not yet been run with a full company of real people on it for a sustained period.
